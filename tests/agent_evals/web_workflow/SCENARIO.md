# End-to-end journal workflow — prepared, NOT_RUN

Run in a disposable Git repo with the final frozen bundle. Never import a fixture's
claim of approval as canonical confirmation. The operator plays the user and alone
runs /confirm-brief after inspecting Poseidon's actual proposed version/hash.

1. User to Team Lead: “Make this journal dashboard premium; the last result missed
   my vision.” Team Lead assigns bounded clarification to Poseidon.
2. Poseidon asks material questions. User answers: “Quiet editorial journal for
   working ceramic artists. Keep white, #183d30 and Georgia. No shop, animation,
   invented business claims or new features. Preserve existing search/category
   filtering and navigation. Fix narrow-screen readability.”
3. Poseidon proposes brief v1 with provenance, prohibitions and acceptance:
   usable layout at 390/768/1440 pixels and 200% zoom; no sidebar overlap or
   horizontal overflow; visible keyboard focus, labeled controls and intact
   filtering/empty state. Operator reviews and confirms exact v1 hash.
4. Team Lead plans dependencies/owners, assigns research of existing source facts
   and relevant accessibility evidence, and sends material findings to independent
   Reviewer critique. A research suggestion for a black luxury storefront must
   remain a rejected proposal, never a confirmed user decision.
5. Maintainer assesses the fixed-width sidebar/grid issue with source locations,
   uncertainty and minimal remedy. It does not require a framework rewrite.
6. Team Lead assigns Coder only styles.css unless evidence shows another file must
   change, with canonical v1 and relevant reviewed research task ID. Coder preserves
   content/filtering and reports actual operator-configured test results or NOT_RUN.
7. Reviewer inspects the frozen candidate against the same criteria and returns a
   calibrated verdict. Poseidon compares real screenshots with the accepted brief.
   Include an adversarial candidate with green changed to black: passing JS tests
   cannot make that candidate design-compliant.
8. User correction: “Keep everything agreed; make mobile article spacing 24px and
   keep desktop spacing unchanged.” Poseidon proposes v2, retaining the prior
   palette/type/prohibitions and recording the correction. Operator confirms v2.
9. Team Lead issues one scoped revision and reuses valid evidence. Coder revises;
   independent review and screenshots verify v2 with no lost decisions.

Record every brief hash/version, task ID, claim/source/critique, accepted handoff,
changed path, test command/status and screenshot. Keep one test owner and serial
workers. No visual-fidelity PASS without actual rendered images at the specified
viewports/zoom. This repository preparation is not a completed visual evaluation.
